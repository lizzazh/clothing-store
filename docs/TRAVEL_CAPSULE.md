# Travel Capsule — інтеграція в Elizabeth's Elegance

## Що додано

- **travel-capsule.html**: окремий інтерфейс підбору мінімального дорожнього гардероба.
- **js/travel-capsule.js**: детермінований модуль підбору комплектів.
- **tests/travel-capsule.test.cjs**: перевірки дат, джерел гардероба, обмежень багажу, погоди та відсутніх речей.
- Навігаційні посилання зі сторінок `index.html`, `my-wardrobe.html`, `ai-stylist.html`, `style-quiz.html`, `capsule-wardrobe.html`.

## Інтеграційні точки

- `WardrobeDB.getAll()` із `js/wardrobe-db.js` — **єдине джерело власних речей** (IndexedDB).
- `localStorage.ai_profile.styleDNA` — враховується під час оцінки кандидатів.
- `AIService.generateStructured()` із `js/ai-service.js` — **лише опціональний** розбір вільного тексту поїздки; запит виконується тільки за явним натисканням кнопки. Фото та речі гардероба не передаються в AI.
- Open-Meteo — короткостроковий погодний прогноз у межах доступного інтервалу. Якщо прогноз недоступний або дата надто далека, використовується введена вручну температура.
- `localStorage.ee_travel_capsule_v1` — останній розрахований план, без фотографій.

## Алгоритм

Для кожного дня формуються завдання «прогулянка» і (за кількістю вечерь) «ресторан». Кандидати створюються тільки з фактичних речей користувача, зі структурною перевіркою:

- сукня + взуття (+ верхній шар за низької температури); **або**
- верх + низ + взуття (+ верхній шар).

Вибирається варіант, який додає найменше нових речей до спільної капсули з урахуванням Style DNA, формальності, сезону та лімітів. Число повторів верху/суконь обмежене, з опцією прання. Якщо повного комплекту немає, система явно позначає непокриті події, замість додавання вигаданих речей.

**Важливо:** це евристичний MVP, не математично доведений глобальний оптимум. Сумісність відтінків, реальна комфортність і посадка в цій версії не верифікуються автоматично.

## Обмеження й перевірка

- Підтримується поїздка до **31 календарного дня** (інтервал від 0 до 30 днів між датами).
- Ліміт кількості речей і пар взуття — жорсткий. Вага перевіряється **лише коли вона задана для всіх обраних речей**. У чинному `WardrobeDB` поле ваги наразі не зберігається, тому зазвичай результат — «невідомо»; **не заявляємо**, що дорожня капсула гарантовано поміститься в ручну поклажу.
- Прогноз на віддалені дати не вигадується.
- Результат залежить від актуальності власного гардероба та повноти категорій.
- AI не приймає фінальне рішення про вибір речей: результат формується кодом `TravelCapsule.plan`.
- Дані гардероба залишаються локальними.
- Рекомендації на льоту не зберігають **фото** в localStorage, лише назви й ID відібраних предметів та структуру календаря.

## Перевірка

Запустити `node --test tests/travel-capsule.test.cjs`. Без залежностей Node.
Потім вручну відкрити `travel-capsule.html` через локальний dev server чи Cloudflare Pages, завантажити власний гардероб і перевірити прогноз, зображення, повторні розрахунки та збереження. Для опціонального AI-розбору потрібен налаштований `/api/key`.

## Що **не** змінено

Не перероблялися наявні `AI Stylist`, `Match Score`, `AI Capsule` чи IndexedDB-схема. Нова функція існує паралельно із дипломною версією й безпечна для перегляду в окремій гілці.

## Наступний розвиток

Моделі ваги/складеного об'єму речей; можливість вручну змінювати подію в певну дату; мультиміста; оптимізація на основі комбінаторної задачі покриття; оцінка погодного ризику та взаємозамінних комплектів; експорт PDF-чекліста.
