# Elizabeth’s Elegance — Pocket Stylist PWA

Мобільна PWA за адресою /mobile/. Використовує той самий WardrobeDB (IndexedDB) і ai_profile.styleDNA, що й Elizabeth’s Elegance. Код додано в окремій гілці, production не зачіпається.

## Реалізовано

- Встановлення на головний екран через webmanifest (standalone), іконки 192/512 і service worker.
- Фото з телефона (стискання у JPEG 840px), картки речей та видалення у власному гардеробі.
- Вибір шести стилів Style DNA; збереження у чинному профілі.
- AI-чат для капсул (поїздки, події, повсякденний одяг), з перевіркою ID речей.
- Локальний резервний режим, коли AI недоступний.
- Збереження останніх 15 капсул без фото в localStorage.
- Опціональна голосова диктовка у браузерах з підтримкою Web Speech API.

## Автоматичне розпізнавання одягу

На сторінці «Мій гардероб» можна ввімкнути чекбокс «Автоматически распознавать фото с AI» (вимкнено за замовчуванням), або натиснути «Распознать выбранное фото» для однієї фотографії.

1. Фото стискається на телефоні до JPEG (макс. 840px).
2. Лише після увімкнення згоди вибране фото через автентифікований POST /api/mobile-vision передається до Google Gemini; якщо він недоступний, до явно налаштованого резервного AI.
3. AI повертає назву, категорію, основний колір, можливі сезони, стилі, формальність і приблизну впевненість.
4. Поля заповнюються як **пропозиція**; користувач може змінити будь-яке поле перед натисканням «Сохранить в гардероб».
5. Фото надалі зберігається у локальному IndexedDB, а не на нашому сервері. Сервер не записує зображення в базу, однак Gemini або резервний провайдер обробляє надіслане зображення за власними умовами сервісу.
6. Без AI або без згоди залишається ручне введення. Зміна/відкликання згоди скидає застарілий результат розпізнавання.

У мобільному UI є окреме поле коду доступу у гардеробі. Після одноразового входу використовується захищена HttpOnly cookie на 30 днів; сам пароль не зберігається у браузері. Фото **не надсилається при створенні капсули**; запит капсули передає лише текстові характеристики речей.

Точність не гарантована: колір на фото залежить від освітлення; сезон і стиль — інтерпретації, а не факти. При низькій впевненості UI показує застереження.

## Активація AI — обов’язкові та опціональні Secrets у Cloudflare

Cloudflare Pages → clothing-store → Settings → Variables and Secrets → Preview:

1. PWA_GEMINI_API_KEY — окремий секретний ключ Google Gemini, **не** старий GEMINI_API_KEY.
2. TRAVEL_PWA_PASSCODE — довгий приватний код доступу (мінімум 16 випадкових символів).
3. Опціонально PWA_GEMINI_MODEL — за замовчуванням gemini-2.5-flash.

Вибрати **Encrypt**, зберегти, створити новий Preview deployment з актуального коміту. Потім у PWA відкрити «AI-подключение» та ввести **значення** TRAVEL_PWA_PASSCODE. Після входу використовується захищена HttpOnly cookie на 30 днів. Жоден API-ключ не передається до браузера.

### AI-резерв для розпізнавання речей і запитів

У тому самому Cloudflare **Preview** додатково можна додати:

- `PWA_OPENROUTER_API_KEY` — **Secret** з ключем OpenRouter. Використовується тільки `openrouter/free` (нульова ціна за токени, але є обмеження безкоштовних викликів). Модель із підтримкою зображень вибирає Free Router автоматично. Ключ береться на https://openrouter.ai/settings/keys.
- **Опціонально, за явного бажання використовувати тарифи Groq:** `PWA_GROQ_API_KEY` — Secret; `PWA_ALLOW_PAID_GROQ_FALLBACK` — текстова змінна зі значенням `true`. Без обох полів **Groq ніколи не викликається**, щоб уникнути несподіваних платних запитів. Для фото використовується Qwen Vision, для тексту GPT-OSS 20B.

Маршрут автоматично: **Gemini → OpenRouter Free → (лише за спеціальним дозволом) Groq**. У разі недоступності всіх AI залишається ручне додавання одягу й локальний підбір капсул. Після успішного запиту UI показує, який провайдер відповів. Секрети, промпти, фотографії й відповідь провайдера не логуються через додатковий модуль. Резерв не гарантує безлімітну кількість запитів: ліміти OpenRouter Free діють окремо, доступність мультимодальних моделей змінюється.

Фото для аналізу передається у зовнішній сервіс тільки після згоди на AI-розпізнавання; для AI-капсули передаються лише текстові дані гардероба. Назви й метадані одягу можуть оброблятися резервним провайдером, якщо основний AI недоступний.

PWA також кешує **тільки валідовані AI-метадані** розпізнаних фотографій за SHA-256 хешем фото (до 35 записів, максимум 30 днів) у localStorage; самі фото не пишуться до цього кешу. Повторне завантаження ідентичного стисненого фото може не витрачати новий AI-запит.

**Тестування:** `node --test tests/mobile-ai-fallback.test.cjs tests/mobile-vision.test.cjs`. Результат тестів із мокованими API не підтверджує фактичну доступність або квоти зовнішніх сервісів; необхідно перевіряти в окремому Preview.

Важливо: у старому проєкті endpoint /api/key все ще повертає legacy AI-ключі в браузер. Новий модуль цей endpoint не використовує і потребує **окремого** нового ключа. Перед публічним масштабуванням старий endpoint слід переробити на безпечний серверний проксі, старі ключі перевипустити та ввімкнути Cloudflare rate limiting.

## Встановлення на телефон

iPhone (Safari): відкрити /mobile/ → Поділитися → На екран Домівки.

Android (Chrome або Samsung Internet): відкрити /mobile/ → Меню → Встановити застосунок.

Відкривати з HTTPS. Після установки застосунок запускається без браузерної рамки. Гардероб зберігається локально: Preview Cloudflare і Production використовують **різні domains**, дані між ними автоматично не переносяться. На іншому телефоні фото також не синхронізуються.

## Тестування

Команди:
- node --test tests/travel-capsule.test.cjs
- node --test tests/travel-capsule.ui.test.cjs
- node --test tests/mobile-pwa.test.cjs

Ручна перевірка:
1. Відкрити PWA на телефоні, перевірити нижню навігацію та скрол.
2. Додати 3–5 власних речей, закрити й відкрити PWA, пересвідчитися, що фото збережено.
3. Обрати Style DNA, повторно відкрити додаток.
4. Скласти капсулу без коду: має бути чітко позначено «локальний підбір».
5. Налаштувати секрети, ввести код і скласти AI-капсулу. У відповіді мають бути лише наявні речі.
6. Перевірити офлайн-відкриття гардероба та локального підбору. AI офлайн не працює.
7. Перевірити, що встановлення на головний екран працює.
8. Спробувати видалити річ, яка входила у старий план: додаток має попередити про невідповідність.

## Обмеження MVP

- Немає акаунтів, синхронізації та автоматичного перенесення гардероба між доменами.
- Вага/об'єм ручної поклажі не вимірюються.
- Реальний прогноз погоди не перевіряється в AI-чаті.
- Локальний алгоритм без AI не повністю розбирає довільні природномовні запити.
- HEIC може залежати від підтримки браузера; JPEG і PNG найнадійніші.


## Запам’ятовування AI-входу

Після першого правильного коду нові фотографії автоматично розпізнаються при включеному дозволі. Браузер надсилає захищену HttpOnly cookie, а **код доступу не повторюється для кожного фото**. Можна відключити AI кнопкою «Отключить AI на этом устройстве». Дійсність сесії — до 30 днів, а при зміні секрету TRAVEL_PWA_PASSCODE всі сесії стають невалідними. Слід увімкнути rate limiting для /api/mobile-auth у Cloudflare перед широким використанням.

На скриншоті Cloudflare вибрано **Production**: ці секрети не обов’язково доступні для Preview. Для тестового посилання /mobile/ потрібно перейти в Variables and secrets → **Preview**, додати ті самі назви двох секретів і заново розгорнути Preview. **Не копіювати значення секретів у GitHub або чат.**

## Перевірка Preview після додавання секретів

Після зміни `PWA_OPENROUTER_API_KEY` у Cloudflare Pages → Preview потрібно створити **нове Preview-розгортання** з актуальної гілки. Старі deployment URL не гарантують доступу до нового секрету. Встановлювати PWA та перевіряти AI слід на URL нового розгортання, доповненому `/mobile/`. Секрети не вводяться в браузер і не публікуються в репозиторії.
